## О проекте

**COSMO-NET** — высокопроизводительный интерактивный веб-сервис класса **Aerospace Mission Control Center** для проектирования и оценки устойчивости низкоорбитальной (LEO) спутниковой группировки связи в северных и приполярных районах.

### Ключевые параметры космического сегмента:
- **Группировка:** 48 спутников на круговой орбите высотой **550 км** с квазиполярным наклонением **87°**.
- **Архитектура орбит:** 3 орбитальные плоскости ($P_1, P_2, P_3$), по 16 аппаратов в каждой, сдвиги $\text{RAAN}$ ($0^\circ, 60^\circ, 120^\circ$), фазирование ($0^\circ, 7.5^\circ, 15.0^\circ$).
- **Очереди запуска:** 3 этапа по 16 аппаратов (интервал 3 месяца).
- **Наземная инфраструктура:**
  - Опорный шлюз: **Мурманск** (`G_MUR`, 68.97° с.ш., 33.07° в.д.).
  - Обслуживаемые терминалы: **C65** (65°N, 60°E), **C70** (70°N, 90°E), **C72** (72°N, 130°E).
- **Целевой показатель доступности связи:** $\ge 90\%$ расчетного времени для каждого терминала.
- **Горизонт расчета:** 86 400 секунд (24 часа), шаг 120 секунд (**720 отсчетов**).

## Архитектура решения и ключевые фичи

### 1. Архитектура: Zero-Latency Client-Side Engine + Python CLI Reference
- **Клиентское расчетное ядро (TypeScript / WebGL):** мгновенный расчет 720 временных отсчетов менее чем за 250 мс прямо в браузере. Позволяет интерактивно менять параметры орбит (RAAN, фазу), переключать очереди запуска и моделировать отказы без сетевых задержек.
- **Эталонный модуль Python (`geometry.py` + `app.py`):** официальный расчётный модуль по спецификации ТЗ для пакетной верификации и автоматизированного тестирования.

### 2. Поддержка всех базовых сценариев проверки жюри
1. **Полная группировка (01_full_constellation.json):** проверка покрытия, сквозных маршрутов и задержек в реальном времени.
2. **Этап развёртывания (1, 2, 3 очереди):** прямой переключатель очереди запуска (`1 оч. 16 КА | 2 оч. 32 КА | 3 оч. 48 КА`) в шапке сервиса с мгновенным пересчетом метрик доступности.
3. **Отказ аппаратов и экспресс-тест:** отключение спутников текущего маршрута в один клик и наблюдение за перемаршрутизацией графа.
4. **Изменение орбит и сохранение вариантов:** настройка углов плоскостей, сохранение снимков конфигурации и сопоставление в модуле сравнения.
5. **Валидация и сброс изменений:** строгая проверка структуры `cosmo-A-1.0` с информативными сообщениями об ошибках и кнопка быстрого сброса параметров к исходным.

### 3. Двухрежимная визуализация
- **2D Арктическая азимутальная полярная проекция:** неискаженное отображение приполярных широт (вид на Северный полюс сверху), зон радиовидимости ($\ge 10^\circ$), сетки межспутниковых лазерных линий (ISL) и активного маршрута.
- **3D Интерактивный орбитальный глобус:** объемная модель Земли на Three.js, кольца плоскостей под углом 87°, пространственные лучи связи и вращение камеры с зумом.

### 4. Временной док и интерактивная Gantt-диаграмма доступности
- Скраббинг от 0 до 86 400 секунд (24 часа) с мультипликаторами скорости (1x, 5x, 30x, 120x, 600x).
- **3-полосная лента доступности** для C65, C70, C72:
  - 🟢 **Зеленый:** сквозной маршрут до шлюза активен.
  - 🟡 **Желтый:** спутник виден, но сеть фрагментирована (**ISL Mesh Partition**).
  - 🔴 **Красный:** нет спутника над абонентом или авария шлюза.
- Клик по любому участку диаграммы мгновенно переносит симуляцию в выбранный момент времени.

### 5. Интеллектуальный диагностический модуль (Root Cause Analysis)
При отсутствии маршрута система четко определяет и отображает причину:
1. `NO_VISIBLE_SATELLITE`: отсутствие активных спутников с углом возвышения $\ge 10^\circ$.
2. `ISL_MESH_PARTITION`: над абонентом есть спутник, но в межспутниковом графе нет связного пути до спутников над Мурманском.
3. `GATEWAY_NO_SATELLITE`: отсутствие спутников в зоне радиовидимости шлюза.
4. `GATEWAY_OUTAGE`: регламентная недоступность наземного шлюза.

### 6. Модуль «Инженерные рекомендации и обоснование»
- **Разбор сетевого парадокса при ISL = 2000 км:** математическое доказательство внутриплоскостного разрыва ($d_{\text{хорда}} \approx 2699\text{ км} > 2000\text{ км}$) и обоснование 176 микроперерывов у C72 при 100% радиовидимости.
- **Анализ уязвимостей:** рейтинг ключевых транзитных КА (cut-vertices) и предложения по резервированию шлюза в восточном секторе Арктики (Тикси / Певек).

## Инструкция по запуску

### Вариант 1: Быстрый запуск Frontend (Рекомендуемый)
```bash
cd frontend
npm install
npm run dev
```
Сервис откроется по адресу: **http://localhost:5173**

### Вариант 2: Запуск с локальным Python Backend
В первом терминале:
```bash
cd backend
python -m pip install -r requirements.txt
python app.py
```
Во втором терминале:
```bash
cd frontend
npm run dev
```

### Вариант 3: Запуск через Docker Compose (в 1 команду)
```bash
docker compose up --build
```
Веб-интерфейс будет доступен по адресу: **http://localhost:3000** (бэкенд: **http://localhost:8000**).

### Верификационный тест математического движка
```bash
python verify_all_scenarios.py
```
Проверяет валидацию, точность формул кинематики, маршрутизацию и экспорт `cosmo-A-result-1.0` на всех 4 базовых сценариях.
